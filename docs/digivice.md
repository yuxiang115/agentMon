# Coding Digivice：实现与项目评估

## 本次完成

复用已有纯 reducer、tuipet 风格半块渲染器、Pi overlay 和三阶段进化特效。新增内容集中在角色、成长呈现和任务奖励修正，没有另起游戏引擎。

- 默认新伙伴是黑球兽（Botamon），进化为滚球兽（Koromon），再到亚古兽（Agumon）。路线参考 [Bandai Agumon Dim 指南](https://toy.bandai.co.jp/assets/vb-digitalmonster/pdf/digimon_startguide.pdf)；等级与 XP 门槛是本项目的设计。
- 三个角色各有 11 个 16×16 调色板姿态，工作状态有不同动作/道具，使用新编写的像素数组。
- 面板显示形态、经验、任务状态、下一进化目标；奖励反馈持续约 4 秒，经验条约 0.9 秒补满；进化复用 2.4 秒蓄力、闪烁、显形。
- `/pet journey` 显示所有条件，最近 20 条奖励持久化，完整界面显示最近 4 条。
- `/pet hatch [name]` 创建新黑球兽；`partners` / `partner <id>` 管理已有伙伴，任务进行中不切换。旧存档不被强制换种或清零。
- 修复重复任务结算虚增计数、中断获得完成奖励、晚到的 THINK_END 打开空任务、改动/失败后仍领取先前验证奖励、跨会话遗留 pending 结果，以及中文名字撑破面板边框的问题。
- 保留手动形态覆盖 `/pet use`，它不是解锁操作，不代表自然进化。

## 成长规则

| 行为 | 经验 |
| --- | --- |
| 完成一次 Pi 请求对应的任务窗口 | 10 |
| 任务在最后改动之后通过验证 | 额外 5 |
| 通过验证且过程中没有失败/纠正 | 再额外 5 |
| 有未奖励的新改动时测试通过 | 3 |
| 有未奖励的新改动时构建通过 | 2 |
| 重复测试同一改动、重复结算、中断任务的完成奖励 | 0 |

重复验证仍计入行为特征，但不反复发验证 XP。首个通过会关闭 dirty gate，测试和构建不会为同一份改动各发一遍经验。

| 进化 | 条件（累计） | 23 XP 的干净任务示例 |
| --- | --- | --- |
| 黑球兽 → 滚球兽 | Lv.2 / 100 XP，完成 ≥3 个任务 | 第 5 个任务后 |
| 滚球兽 → 亚古兽 | Lv.3 / 300 XP，完成 ≥8 个任务，验证任务 ≥2 | 第 14 个任务后 |

每次任务结算最多进化一次。成长路线不使用终身照顾失误上限，避免新手永久无法进化。Byte 的旧分支规则保留。

## 最值得继续优化的工程问题

| 优先级 | 代码位置与现状 | 建议 |
| --- | --- | --- |
| P0，多实例使用前 | `packages/storage/store.ts` 无跨进程锁；`json.ts` 共用 `state.json.tmp` | 唯一临时文件 + 跨进程锁/单写入者；加入两进程竞争回归。原子 rename 只防半文件，不能防丢失更新。 |
| P1，奖励可信度 | `packages/adapters/pi/map.ts` 在 tool_call 阶段计 CODE_WRITE；命令分类靠正则，settled 仅证明请求结束 | 成功的写入结果才确认代码变更；读取最终 assistant 错误状态；以工具 ID + 任务 ID 去重。将“请求完成”和“验收成功”区分。 |
| P1，交错验证 | `reducer.ts` dirty gate 不记录验证启动时的代码版本；一个 pass 可清掉另一种验证的失败 | 引入 revision 与 validation run ID，把 pass 绑定到被验证的版本；测试/构建分别记录未解决的失败。 |
| P1，常驻性能 | `widget.ts` 定时读取 `store.read()`，每帧同步读盘、JSON parse、tick | 内存快照 + 事件驱动保存；文件变更才失效，保持跨进程更新可见。 |
| P1，小终端布局 | overlay 高度随精灵尺寸与成长信息增长，可能遮挡内容 | 自动收起、紧凑状态栏/底部 widget；可选减少动态效果。 |
| P1，存档容错 | `json.ts` 只验证顶层形状，读文件异常被当成不存在 | 逐字段校验并迁移；区分不存在、权限错误、损坏；权限错误时禁止覆盖保存。 |
| P2，导入体验 | `index.ts` 按空白拆分导入命令，带空格路径容易误解 | 支持引号、文件选择和导入预览；进化规则注册按包版本替换，避免热重载重复。 |

以上是明确保留的后续工作，当前版本仍以单 Pi 会话为主要使用方式。

## 后续功能建议（推荐顺序）

1. **项目伙伴绑定**：每个 Git 项目对应一只伙伴，跨会话保持同一成长记录；避免项目切换时 XP 串到另一只。
2. **成长图鉴与里程碑**：显示亲自养出的形态、进化时间、首个测试通过/第一次修复失败等；成就奖励设置一次性标记。
3. **更长的亚古兽路线**：暴龙兽、机械暴龙兽、战斗暴龙兽。后期条件由验证任务、修复任务、完整功能交付构成，避免只看工具调用次数。
4. **任务战斗表现**：测试失败显示受击，修复通过显示反击，任务完成显示胜利；不让普通调试失败导致永久负面结果。
5. **照顾互动**：喂食、训练、睡眠和亲密度；仅作为可选互动，不要求用户频繁操作才能继续写代码。
6. **多 Agent 小队**：先完成存储并发和事件归属，再支持主 Agent 与子 Agent 分别对应伙伴。

## 运行与验证

```sh
npm test
npm run typecheck
npm run demo:device
npm run demo:device -- --export out/device-preview.html
pi -e ./packages/pi-extension/index.ts
```

演示使用真实 reducer 和 PetOverlay，任务加速，只使用内存状态。HTML 为录制帧的离线交互回放；PNG 是实际精灵的像素预览。自动测试覆盖完整双阶段进化、重复结算、中断、验证过期、奖励日志上限、中文/窄终端、进化阶段，以及 Pi 事件到存档的集成。没有在真实交互式 Pi 会话内做人工验收。
